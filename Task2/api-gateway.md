# API Gateway для DSP-интеграции


### Маршрутизация запросов на ставки
Через 3 месяца:

1. Запросы от новой DSP проксируются на внутренний кластер Сервиса Ставок
2. Весь остальной функционал по-прежнему работает в монолите и в Gateway API не обращается

Через год:

1. Сервис B2B Gateway Api проксирует все запросы от всех DSP на Bidding Service
2. Сервис B2С Gateway Api проксирует все запросы от всех клиентов на Delivery Service
3. Сервис Dashboard Gateway Api проксирует все запросы от личного кабинета рекламодателя на сервис Advertiser Dashboard


### Ограничение частоты запросов

1. Выставлем лимит для каждой DSP-площадки в завимости от договоров
2. При возникновении кратковременных всплесков Gateway API буферизирует избыток
3. При долгосрочном превышении Gateway API срезает лишние запросы

### Аутентификация
Используем mTLS - узнаем потребителя по сертификату


### Паттерн Автоматического размыкателя
Настраиваем Envoy Proxy на отслеживание аномалий. 

Если Bidding Service возвращает ошибки или таймауты/долгие ответы больше определенного процента, то перестаем пропускать запросы к Bidding Service, сразу с уровня Gateway отдаем ошибку, чтобы не усуглять проблемы в ИС.

Через N секунд запускаем Y% трафика, если ошибки ушли, то возвращаем трафик

### Мониторинг времени отклика
Шлюз Envoy собирает телеметрию и отправляет её в связку Prometheus + Grafana. 

Собираем метрику времени ответа от Bidding Service. Выводим графики в Grafana. Настраиваем Графану на отправку алертов.
