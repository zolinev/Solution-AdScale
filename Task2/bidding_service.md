# Сервис ставок

### Границы сервиса:
 
Основная задача сервиса — принять запрос от DSP, максимально быстро определить подходящую ставку и вернуть ответ. Представляем собой объединные модули AdServer и AuctionEngine из текущего монолита

Функционал:

1. Прием Bid Request по стандарту OpenRTB.
2. Фильтрация рекламных кампаний по условиям (геолокация пользователя, ОС и тд)
3. Проверка достаточности бюджета рекламодателя.
4. Выбор наибольшей ставки (бизнес-логика аукциона).
5. Формирование ответа Bid Response.

### Зависимости от других сервисов
Так как сервис высоконагружен и критичен по latency, то он должен быть максимально автономен.
Сервис принимает вызов от сервиса B2B Gateway API, за данными для проведения аукциона обращается либо в read-реплику Postgre (в горизонте трех месяцев), либо в кеш Redis (в горизонте года)


###API сервиса
Приложено в в bidding_service.yaml

###Модель данных
Для ускорения работы сервиса в горизонте 3х месяцев, данные для проведения ауциона должны храниться в денормализованном виде. 

campaign_id - INTEGER - id кампании  
geo - VARCHAR(2) - код региона пользователя  
os - VARCHAR(20) - операционная система пользователя ('Android', 'iOS')  
width - INTEGER - ширина баннера в пикселях  
height - INTEGER - высота баннера в пикселях  
price - NUMERIC(6,2) - цена за показ  
is_active - BOOLEAN - флаг доступности бюджета
