#Кэширование

Для ускорения работы сервисов горячего пути Bidding Service и Delivery Service необходимо кешировать кампании, бюджеты, победителей аукционов.

Кластер Redis необходимо размещать физичиески максимально близко к инстансами сервисов Bidding Service и Delivery Service для снижения временных затрат на сетевое взаимодействие

Для кампаний и бюджетов TTL=0 (бесконечно), стратегия инвалидации - по событию.
Для победителей аукционов TTL - несколько минут - если в течение этого времени клиент не пришел за банером, значит уже не придет

Прогрев кеша:

1. При необходимости полного прогрева кеша подаем команду в соответствующий продуктовый сервис (для кампаний - Campaign Service, для бюджетов - Financial Service)
2. Сервис выбирает данные из своей БД и пачкам по N штук складывает в Кафку
3. Сервис Cache Actuator выбирает данные из Кафки и пишет их в Redis точно так же, как если бы это был не прогрев кеша, а штатная работа
